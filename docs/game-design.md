# PocketCard 대전 — 설계 v0.2 (2026-11-18)

웹 = 두 사람이 함께 보는 **공용 게임판**, 폰 앱(Godot) = 각자의 **비공개 손패·조작기**, PC의 Node 서버 = **게임 상태와 규칙의 유일한 원본**.

- v0.1 → v0.2: Fable 모델 리뷰(`docs/game-design-review-fable.md`)와 **6개 덱 카드 전수 조사**(`src/data/rules/survey.json`, 6장)를 반영했다.
- 규칙 근거는 공식 Advanced Player's Rulebook Ver 3.4(2025, 아시아판) 원문이다. 한국은 아시아·일본 규칙을 따른다.
- 마지막 장(15장)에 **아직 정해야 할 사항**을 모았다.

## 0. v0.1에서 바뀐 점

| 구분 | v0.1 | v0.2 |
|---|---|---|
| 자동/수동 경계 | 기본 규칙 자동 + 카드 효과 수동 | 계속 걸리는 효과(도구·스타디움·특수 에너지·테라스탈·데미지 보정)는 **처음부터 자동**, 1회성 효과만 수동 허용. 엔진 판정은 **상대 승인 아래 수정** 가능 (5장) |
| 효과 없는 대전 단계 | 4단계 "바닐라 대전" | 삭제. 기술 83개 중 58개가 효과를 가진 것을 조사로 확인 (6장) |
| 혼란 회복 | 다음 턴 끝에 회복으로 읽힘(오류) | 벤치로 가거나 진화해야 회복 |
| 데미지 | 데미지 카운터와 구분 없음 | "데미지"와 "데미지 카운터 올리기"를 구분 |
| 테라스탈 | 카드 효과 | **룰**(벤치에서 기술 데미지를 받지 않음) |
| 기절 확인 | 기술 뒤·체크 뒤만 | **모든 효과 처리 뒤** 기절 루틴 |
| 동시 승패 | 무승부 → 서든데스(사이드 1장) | 공식 표(4.9): 조건을 더 많이 만족하면 승리, 같으면 무승부, 승자가 꼭 필요하면 **타이브레이커(사이드 6장, 먼저 적어진 쪽 승리)** |
| 벤치 | 5칸 고정 | **가변 (최대 8칸, 제로의 대공동)** |
| 로스트존·빛나는 포켓몬 | 지원 | 6개 덱에 관련 카드가 없어 **범위에서 제외** |
| 접속 | QR + 세션 코드 | 같은 Wi-Fi **자동 탐색 + IP 입력**을 먼저, QR은 나중 단계 |
| 사이드 선택 | 게임판에서 | **폰에서** |
| 카드 확대 방향 | 주인 쪽 + 뒤집기 버튼 | **양방향 2장 동시 표시** (뒤집기는 보조) |
| 특수상태 표시 | 카드 회전 | **배지** (180° 진영과 충돌 방지) |
| 폰 화면 | 패/내 트래쉬/상대 트래쉬 | + **필드**(필수), 로그. 많은 카드는 격자 보기 |
| 구현 순서 | 화면 → 엔진 | **엔진 먼저**(헤드리스 테스트), 한 매치업 끝까지 → 확장 |
| 한글 데이터 | 필요 없음 | **기술명·특성명 한글 데이터 필요** |

## 1. 목표와 범위

| 구분 | 내용 |
|---|---|
| 목표 | 실제 카드 없이, 큰 화면 1대 + 폰 2대로 포켓몬 카드게임 1:1 대전 |
| 덱 | 앱의 코리안리그 우승 덱 6종 고정 (부스터 ex, 드래펄트 ex, 리자몽 ex, 타부자고 ex, 가디안 ex, 파쪼옥), 각 60장, 서로 다른 카드 120종 |
| 규칙 | 공식 규칙 전체 + 6개 덱의 카드 효과 |
| 범위 밖 | 로스트존, 빛나는 포켓몬, VSTAR·GX 마커 (덱에 없음), 온라인 원격 대전, 관전, AI 상대, 덱 편집 |

신뢰 모델: 친구끼리의 대전이다. 서버를 띄운 PC의 주인은 원칙적으로 서버 메모리를 볼 수 있다. 서버 콘솔과 로그 파일에는 비공개 정보를 출력하지 않는다.

## 2. 시스템 구성

```
 ┌──────────────────── 같은 Wi-Fi ────────────────────┐
 │  [PC] 게임 서버 (Node, WebSocket, UDP 알림)          │
 │    ├─ 규칙 엔진 (TypeScript, 결정적 함수)             │  ← 상태의 유일한 원본
 │    ├─ 저장: 시드 + 입력 로그 (디스크)                 │  ← 서버가 꺼져도 복구
 │    └─ 웹 게임판 (React, 브라우저 전체 화면)            │
 │  [폰 A]  Godot 앱 ─┐                                │
 │  [폰 B]  Godot 앱 ─┴─ WebSocket ─ 서버               │
 │  [개발용] 웹 디버그 폰 /dev/phone?p=1|2               │
 └────────────────────────────────────────────────────┘
```

원칙:
1. **엔진은 결정적 함수**: `(상태, 입력) → (새 상태, 이벤트[], 대기 중인 선택 요청)`. 난수는 시드 기반 (`crypto` 시드 + Fisher–Yates 셔플).
2. **시드 + 입력 로그를 디스크에 저장**: 서버 재시작 시 리플레이로 복원, 버그 재현, 되돌리기(제한적)에 사용.
3. **스냅숏이 진실, 이벤트는 연출용**: 매 변경마다 각 클라이언트에 **그 사람 시점의 전체 스냅숏 + 버전 번호**를 보낸다. 상태가 작아서 차분 동기화는 필요 없다. 재접속은 스냅숏 + 대기 중인 요청만 다시 보내면 끝난다.
4. **폰은 규칙을 모른다**: 서버가 "지금 할 수 있는 행동 목록 + 못 하는 이유"를 함께 보낸다. GDScript에 규칙을 이중으로 구현하지 않는다.
5. **덱은 서버가 구성**: 폰은 덱 ID와 인쇄 선택만 보낸다. 카드는 **규칙 ID**(같은 카드면 인쇄가 달라도 같음)와 **인쇄 코드**(이미지)를 분리한다.
6. **버전 확인**: 접속할 때 프로토콜 버전과 카드 데이터 버전을 비교하고, 다르면 거절하고 안내한다 (APK와 서버의 카드 목록 불일치 방지).

## 3. 접속 / 로비

### 3.1 폰이 서버를 찾는 방법
| 순서 | 방법 | 비고 |
|---|---|---|
| 1 (기본) | **자동 탐색**: 서버가 같은 Wi-Fi에 UDP로 "게임 있음"을 알리고, 앱은 목록("○○ PC의 게임 · 코드 482913")에서 탭 | Godot `PacketPeerUDP`, 추가 플러그인 불필요 |
| 2 (예비) | **주소 직접 입력**: 게임판에 표시된 `192.168.0.12:8787` + 세션 코드 | 공유기가 브로드캐스트를 막을 때 |
| 3 (나중) | **QR 스캔** | Android 플러그인 필요 (13장 단계 8) |

- 6자리 세션 코드는 **주소가 아니다**: 탐색 목록에서 맞는 게임을 고르거나, 주소 입력과 함께 쓴다.
- 서버는 PC의 네트워크 주소 후보(VPN·WSL·Hyper-V 같은 가상 어댑터 제외 우선)를 로비에 나열하고, 사용자가 고를 수 있게 한다.
- 로비에 안내: Windows 방화벽 인바운드 허용, 게스트 Wi-Fi(기기 간 통신 차단)에서는 안 됨.
- 참가하면 **개인 토큰**을 발급해 앱에 저장 → 같은 자리로 재접속. 세션 코드나 QR만으로는 이미 찬 자리를 뺏을 수 없다.

### 3.2 웹 로비 화면
```
┌───────────────────────────────────────────────────────────────┐
│                 ★  POCKETCARD BATTLE  ★   (큰 로고)            │
│                                                               │
│   앱에서 [게임 참가] → 목록에서 이 게임을 고르세요                 │
│   세션 코드 482 913 · 주소 192.168.0.12:8787 [주소 바꾸기 ▾]     │
│   (QR — 13장 단계 8 이후 표시)                                  │
│                                                               │
│   ┌─ 플레이어 1 ─────────────┐   ┌─ 플레이어 2 ─────────────┐  │
│   │ ● 연결됨  (Galaxy Fold) │   │ ○ 대기 중                │  │
│   │ 덱: 드래펄트 ex          │   │ 덱: -                    │  │

│   └─────────────────────────┘   └─────────────────────────┘  │
```

- 슬롯 상태: `대기 중 → 연결됨 → 덱 선택함 → 준비 완료` (실시간). 준비 완료는 해제 가능.
- 같은 덱끼리 대전 허용 (카드 개체 ID는 플레이어별로 분리).

### 3.3 앱 흐름
```
[메인] 덱 보기(기존) | 게임 참가(신규)
  └ 게임 참가 → 게임 목록(자동 탐색) / [주소 입력]
      └ 연결 → "플레이어 1로 참가" → 덱 선택(기존 목록, 고른 인쇄 사용) → [준비 완료]
          └ 게임 화면 (9장)
```
- 연결 유지: 하트비트, 앱이 다시 앞으로 오면 자동 재접속, 게임 중 화면 꺼짐 방지.
- 폰이 고장 나면 **자리 인계**: 새 기기로 참가 → 게임판에서 승인.

## 4. 게임 규칙 (공식 규칙 기준)

### 4.1 덱 규칙
- 60장, 같은 **이름** 최대 4장(기본 에너지 무제한, 특수 에너지는 4장 제한 적용), ACE SPEC 덱당 1장, 기본 포켓몬 1장 이상.
- 이름은 카드 코드가 아니라 카드 이름 기준 (인쇄가 달라도 같은 이름, "부스터"와 "부스터 ex"는 다른 이름).
- 덱이 고정이므로 **실행 중 검사가 아니라 데이터 테스트**로 검증한다 (12장).
- 레귤레이션 검사는 하지 않는다 (덱에 G 마크 카드 포함, 15장 D6).

### 4.2 게임 준비
1. 코인 토스 → 이긴 사람이 **패를 보기 전에** 선공/후공 선택.
2. 각자 셔플 → 7장 드로우.
3. 기본 포켓몬 확인
   - 둘 다 있음 → 각자 배틀 포켓몬 1장 뒷면 배치.
   - 한 사람만 없음 → 없는 사람은 패를 공개(상대가 폰에서 [확인] 누를 때까지 표시)하고 덱에 섞어 다시 7장. 기본 포켓몬이 나올 때까지 반복, **횟수 기록**. 상대는 먼저 6·7번(벤치, 사이드)을 진행할 수 있다.
   - 둘 다 없음 → 서로 공개 후 둘 다 다시 (횟수에 넣지 않음).
4. 벤치에 기본 포켓몬 0~5장 뒷면 배치.
5. 덱 위 6장을 사이드로 뒷면 배치 (덱 반대편).
6. 상대의 멀리건 횟수만큼 **0~N장 추가 드로우 선택**, 그중 기본 포켓몬은 벤치에 낼 수 있음. (양쪽 모두 멀리건한 경우의 처리 — 규칙서 문구상 각자 상대의 횟수 기준. 확인 필요)
7. 배틀·벤치 포켓몬을 모두 앞면으로 → 게임 시작.

- 셋업 중 뒷면 포켓몬의 내용은 **상대와 게임판에 보내지 않는다**.

### 4.3 턴 구조
```
[턴 시작]  1장 드로우 — 드로우할 수 없으면 패배
[행동]     아래를 원하는 순서·횟수로
  · 기본 포켓몬을 벤치에 (한 장씩, 벤치 칸 수까지)
  · 진화 (4.4)
  · 에너지 붙이기 — 손에서 붙이는 것만 턴당 1번 (효과로 붙이는 것은 별개)
  · 아이템 — 무제한
  · 포켓몬의 도구 — 포켓몬당 1장, 임의로 떼거나 교체 불가
  · 서포트 — 턴당 1장 (선공 첫 턴 불가)
  · 스타디움 내기 — 턴당 1장, 같은 이름이 나와 있으면 불가, 새 스타디움이 기존 것을 트래쉬
  · 스타디움 효과 사용 — "그 플레이어는 ~해도 된다" 유형, 플레이어별 턴당 1번 (스타디움이 바뀌면 다시 가능)
  · 특성 사용 — 4.10
  · 후퇴 — 턴당 1번
[기술]     배틀 포켓몬의 기술 1개 (선공 첫 턴 불가) 또는 기술 없이 턴 종료
[턴 종료]  "자신의 차례가 끝날 때" 효과 (예: 기술머신 에볼루션 트래쉬)
[포켓몬 체크] 4.6 — 어느 쪽의 턴도 아님
→ 상대 턴
```
- 카드를 사용해도 게임 상태가 전혀 바뀌지 않거나 사용 조건을 만족하지 못하면 사용할 수 없다 (아이템·서포트·스타디움·특성).
  - 예외: 덱(비공개)을 찾는 효과는 대상이 없을 수도 있으므로 **덱이 1장 이상이면 사용 가능**.
- 기술은 효과가 없어도 선언할 수 있다.

### 4.4 첫 턴 / 진화
- **선공의 첫 턴: 기술·서포트 불가.** 후공의 첫 턴은 둘 다 가능. "첫 턴"은 플레이어별로 추적한다.
- 양쪽 모두 **자기 첫 턴에는 진화 불가**. 이번 턴에 나온 포켓몬, 이번 턴에 진화한 포켓몬도 진화 불가.
  - 카드 효과가 예외를 만든다 (이브이의 "부스트 진화": 배틀 필드에 있으면 첫 턴·나온 턴에도 진화 가능).
- **이상한사탕**: 기본 포켓몬에 2진화를 바로 올린다. 일반 진화와 같은 제한(첫 턴, 이번 턴에 나온 기본 포켓몬 불가). 2진화 → 1진화 → 기본 **2단계 진화 계열 데이터**가 필요하다. 사탕으로 진화하면 밑에 1진화 카드가 없다.
- 이상한사탕으로 진화해도 "손에서 내어 진화시켰을 때" 특성은 발동한다 (리자몽 ex).
- 진화하면 에너지·도구·데미지 카운터 유지, 특수상태와 포켓몬에 걸린 효과는 사라짐. 진화 전 단계의 기술·특성은 쓸 수 없음. 진화하면 **새 포켓몬**으로 취급(특성 사용 기록 초기화).
- 메가진화 ex는 진화해도 턴이 끝나지 않는다 (현행 규칙).

### 4.5 기술과 데미지
**선언 → 확인 → 처리 순서**
1. 기술 선언: 잠듦·마비면 불가, 에너지가 비용에 맞아야 함 (4.11)
2. 기술 실패 확인: "기술이 실패할 수 있는" 효과의 코인, **혼란**이면 코인 (뒷면: 자신에게 데미지 카운터 3개, 턴 종료)
3. "데미지를 주기 전에" 효과
4. 데미지 계산 (상대 **배틀 포켓몬**에게 주는 기술 데미지)
   1. 기술 데미지 (+, −, × 적용). × 또는 −로 0 이하가 되면 계산 종료
   2. 공격하는 쪽에 걸린 효과 (카지 +30, 태권왕의 수련 +40, 오기머리띠·부스트에너지 미래 등). 0 이하면 종료
   3. **약점** (보통 ×2) — 공격 포켓몬의 **타입** 기준 (테라스탈은 타입과 에너지 비용 색이 다를 수 있음)
   4. **저항력** (보통 −30). 0 이하면 종료
   5. 받는 쪽에 걸린 효과 (메가디안시 ex −30 등). 0 이하면 종료
   6. 최종 데미지 → 데미지 카운터 (10당 1개). "데미지를 받지 않는다"면 0
5. 데미지 외 효과 (적힌 순서대로)
6. "데미지를 받았을 때" 효과
7. 기절 루틴 (4.7)

**데미지 vs 데미지 카운터**
- **데미지 카운터를 올리는 효과는 데미지가 아니다**: 약점·저항력, 데미지 증감, "데미지를 받지 않는다", "데미지를 받았을 때" 모두 적용 안 됨.
  - 해당 카드: 드래펄트 ex(벤치에 카운터 6개), 루차불, 미라몽·야느와르몽(카운터 5·13개), 이야후(카운터 옮기기), 가디안 ex(자기 포켓몬에 카운터 2개), 혼란 자해 3개.
- 약점·저항력은 **상대 배틀 포켓몬에게 주는 기술 데미지에만** 적용. 벤치·자신의 포켓몬에게는 미적용.
- **테라스탈 룰**: 테라스탈 포켓몬은 **벤치에 있는 한 기술의 데미지를 받지 않는다** (양쪽 기술 모두). 특성 무효로 꺼지지 않으며, 데미지 카운터를 올리는 효과는 막지 못한다.

### 4.6 특수상태 (배틀 포켓몬에게만)
| 상태 | 효과 | 회복 |
|---|---|---|
| 독 | 포켓몬 체크마다 데미지 카운터 1개 (카드에 따라 더 많음) | 벤치로 감, 진화, 카드 효과 |
| 화상 | 체크마다 카운터 2개, 그다음 코인 앞면이면 회복 | 벤치로 감, 진화, 카드 효과, 코인 |
| 잠듦 | 기술·후퇴 불가. 체크마다 코인 앞면이면 회복 | 벤치로 감, 진화, 카드 효과, 코인 |
| 마비 | 기술·후퇴 불가 | **걸린 포켓몬 주인의 다음 턴이 끝난 뒤 체크에서** 회복, 또는 벤치로 감, 진화, 카드 효과 |
| 혼란 | 기술 선언 시 코인, 뒷면이면 실패 + 자신에게 카운터 3개. **후퇴는 가능** | 벤치로 감, 진화, 카드 효과 (**자동 회복 없음**) |

- 독·화상은 마커라 다른 상태와 겹칠 수 있다. 잠듦·마비·혼란은 서로 배타적(새로 걸린 것으로 교체).
- 교체 효과로 벤치에 가도 회복 (교체는 후퇴가 아니라 턴 1회 제한, 잠듦·마비 제한과 무관).
- **포켓몬 체크**: 매 턴이 끝난 뒤 **양쪽 배틀 포켓몬 모두**에 대해 진행. 독 → 화상 → 잠듦 → 마비 → 체크 때 발동하는 카드 효과 (여러 개면 **다음 차례 플레이어가 순서 결정**) → 기절 루틴.
- 6개 덱에서 특수상태를 거는 카드는 **이야후(혼란)** 뿐이다. 가디안 ex의 기술이 자신의 특수상태를 회복한다.

### 4.7 기절 루틴 (모든 효과 처리 뒤 실행)
기절은 기술 뒤와 포켓몬 체크 뒤뿐 아니라 **특성·트레이너스·최대 HP 변화 직후**에도 생긴다 (미라몽·야느와르몽의 자폭 특성, 그래비티 마운틴의 2진화 최대 HP −30, 재밍타워로 용기의부적 HP +50이 사라짐 등). 엔진은 **모든 효과 처리 뒤** 다음 루틴을 돌린다.

1. 남은 HP ≤ 0 (데미지 합계 ≥ 최대 HP) 인 포켓몬을 모두 찾는다.
2. 기절할 때 발동하는 효과 처리 (피카츄 ex "버티는 하트": HP 만땅에서 기술 데미지로 기절하면 HP 10으로 남음 — 이 경우 기절하지 않음, 학습장치 등)
3. 기절한 포켓몬과 붙은 카드 전부 트래쉬
4. **상대가 사이드를 가져간다** (일반 1장, 포켓몬 ex 2장, **메가진화 ex 3장**, 효과로 추가: 브라이어 +1, 무쇠손 ex +1). 여러 마리면 합산, 남은 사이드보다 많으면 남은 만큼.
   - 자신의 효과로 자기 포켓몬이 기절해도(자폭 특성) **상대가** 사이드를 가져간다.
   - 사이드는 가져가는 사람이 **폰에서** 뒷면 중 위치를 고른다.
5. 승패 확인 (4.9)
6. 배틀 포켓몬이 없어진 쪽은 벤치에서 새 배틀 포켓몬을 낸다. 양쪽이면 **다음 턴 플레이어가 먼저**.
7. 턴 중간이었다면 턴은 계속된다.

- **턴별 기절 기록**: "앞의 상대 차례에 자신의 포켓몬이 기절했다면"(기로치 ex), "사이드 장수 비교"(카운터 캐처, 오기머리띠) 조건에 쓴다. 포켓몬 체크 중 기절은 어느 쪽의 턴도 아니므로 "상대 차례에 기절"에 포함하지 않는다.

### 4.8 효과의 지속 시간과 귀속
| 귀속 | 예 | 사라지는 때 |
|---|---|---|
| 포켓몬 개체 | "다음 자신의 차례, 이 포켓몬은 기술 불가"(부스터 ex, 다투곰, 라티아스, 미라이돈), "다음 상대 차례, 도망칠 수 없다"(오거폰, 야느와르몽), 데미지 감소(게노세크트 ex), 받는 데미지 무효(테라파고스 ex) | 지정 시점 또는 **벤치로 가거나 진화하면** |
| 플레이어 | "다음 상대 차례, 상대는 아이템 불가"(꼬몽울, 탱그릴), "이번 차례 데미지 +30/+40"(카지, 태권왕), 브라이어 | 지정 시점 (공격한 포켓몬이 떠나도 유지) |
| 계속 효과(출처가 필드에 있는 동안) | 도구, 스타디움, 특성(라티아스 ex, 클레피, 릴리에의 삐삐 ex, 메가디안시 ex, 게노세크트), 특수 에너지 | 출처가 사라지면 |

- 만료 시점 종류: 이번 차례 끝, 다음 상대 차례 끝, 다음 자신의 차례 끝.
- 효과 객체 = {대상, 내용, 만료 시점, 출처}. 계속 효과는 매번 출처에서 다시 계산한다.

### 4.9 승패 (공식 표)
조건: ① 사이드를 모두 가져감 → 승리, ② 상대 필드에 포켓몬이 없음(배틀 포켓몬을 낼 수 없음) → 승리, ③ 상대가 턴 시작에 드로우하지 못함 → 승리.

양쪽이 동시에 조건을 만족하면 아래 공식 표를 따른다 (규칙서 E장).

| 내가 사이드 다 가져감 | 상대가 사이드 다 가져감 | 내가 낼 배틀 포켓몬 없음 | 상대가 낼 배틀 포켓몬 없음 | 결과 |
|:-:|:-:|:-:|:-:|:-:|
| ● | | ● | | 무승부 |
| | ● | | ● | 무승부 |
| ● | ● | ● | ● | 무승부 |
| ● | ● | | | 무승부 |
| | | ● | ● | 무승부 |
| ● | ● | | ● | **승리** |
| ● | | ● | ● | **승리** |
| ● | | | ● | **승리** |
| ● | ● | ● | | **패배** |
| | ● | ● | ● | **패배** |
| | ● | ● | | **패배** |

- 요약: **조건을 더 많이 만족한 쪽이 이기고, 같으면 무승부.**
- 승자가 꼭 필요하면 **타이브레이커**: 처음부터 새 게임, 사이드 6장, **상대보다 사이드가 먼저 적어진 쪽이 승리**.
- 항복 버튼, 결과 화면, 재대전(덱 유지/교체)을 둔다.

### 4.10 특성 사용 추적
| 종류 | 예 | 추적 |
|---|---|---|
| 횟수 제한 없음 | 가디안 ex "사이코 임브레이스"(몇 번이든) | 없음 |
| 개체별 턴 1회 | 뮤 ex, 타부자고 ex, 피죤투 ex, 드래런치, 게노세크트 ex, 미라이돈 ex, 이야후 | 포켓몬 개체별 플래그 (필드를 떠났다 오거나 진화하면 새 개체) |
| 같은 이름 턴 1회 | 기로치 ex "역으로 취하다", 피죤투 ex "마하 서치", 스핀로토무 "팬콜", 루나톤 "루나 사이클" | 플레이어·턴별 이름 플래그 |
| 유발형 (선택) | 리자몽 ex·야부엉(손에서 진화시켰을 때), 루차불(손에서 벤치에 냈을 때) | 발동 시 "사용할까요?" 요청 |
| 계속형 (자동) | 라티아스 ex, 클레피, 릴리에의 삐삐 ex, 메가디안시 ex, 게노세크트, 전툴라, 파이리, 다투곰 붉은 달 ex, 이브이, 이브이 ex, 피카츄 ex | 계속 효과로 계산 |
| 특수 조건 | 스핀로토무(자신의 첫 턴만), 기로치 ex(앞 상대 턴 기절), 루나톤(솔록이 필드에, 에너지 트래쉬) | 조건 검사 |

- **특성 무효**: 클레피 "장난 잠금"이 배틀 필드에 있으면 양쪽 **기본 포켓몬**의 특성이 없어진다 (클레피 자신 제외). 계속형 특성 계산에도 반영.

### 4.11 에너지
- 기본 에너지 1장 = 그 타입 1개.
- 특수 에너지 (6개 덱):
  | 카드 | 제공 |
  |---|---|
  | 제트 에너지 | 무색 1개. 손에서 벤치 포켓몬에 붙이면 그 포켓몬을 배틀로 교체 |
  | 네오 어퍼 에너지 (ACE SPEC) | 무색 1개, 2진화에 붙어 있으면 모든 타입 2개 |
  | 루미너스 에너지 | 모든 타입 1개, 다른 특수 에너지가 함께 붙어 있으면 무색 1개 |
- 기술·후퇴 비용 충족 판정은 **매칭 문제**(여러 타입을 제공하는 에너지의 배분)로 푼다.
- 비용 변경(반짝이는 결정: 테라스탈 기술 비용 1개 감소, 다투곰 붉은 달 ex: 상대가 가져간 사이드만큼 감소)과 에너지 제공은 별개로 모델링.
- 후퇴할 때 어떤 에너지를 트래쉬할지 **선택 요청**. 후퇴 비용 변경: 풍선(−2), 라티아스 ex(기본 포켓몬 0), 파이리(에너지 없으면 0), 부스트에너지 미래(미래 포켓몬 0).

### 4.12 덱·공개 정보
- 효과로 드로우할 때 덱이 부족하면 있는 만큼만 (패배 아님). "덱 위 N장 보기"도 있는 만큼.
- 서치: 조건이 붙은 서치("기본 포켓몬 1장")는 못 찾았다고 할 수 있다. 조건 없는 서치("좋아하는 카드 1장", 피죤투 ex)는 반드시 가져와야 한다. 상대는 대상이 없었는지 일부러 안 가져갔는지 구분할 수 없어야 한다.
- 셔플하지 않는 덱 조작: 드래런치(위 2장 중 1장, 나머지 **덱 아래**), 암호마니아의 해독(2장을 골라 **덱 위**에 원하는 순서), 모야모(패를 **덱 아래**로).
- "상대에게 보여주고 패에 넣는다"는 카드는 **게임판에 공개**, 상대가 폰에서 [확인]할 때까지 표시.
- 사용 중인 아이템·서포트는 **"사용 중" 구역**에 두었다가 효과가 끝나면 트래쉬 (자기 자신 회수 방지).
- 패·덱·사이드·트래쉬 장수는 항상 공개.

### 4.13 기타
- 벤치 칸 수 가변: **제로의 대공동** — 테라스탈 포켓몬이 있는 플레이어는 벤치 8칸. 스타디움이 트래쉬되거나 테라스탈이 없어지면 5칸이 될 때까지 트래쉬 (양쪽이면 스타디움 주인부터).
- 재밍타워: 양쪽 도구 효과 전부 없음 → 용기의부적 HP +50이 사라져 즉시 기절할 수 있음.
- 그래비티 마운틴: 양쪽 2진화 최대 HP −30.
- 릴리에의 삐삐 ex: 상대 포켓몬 전원의 약점을 (데이터상 아이콘 누락, 확인 필요: 초) 타입으로.
- 게노세크트 "에이스 캔슬러": 도구가 붙어 있으면 상대는 ACE SPEC을 손에서 사용 불가.
- 기술 복사: 뮤 ex "게놈 해킹"(상대 배틀 포켓몬의 기술 사용), 기술머신 에볼루션(카드에 적힌 기술 사용, 차례 끝에 트래쉬).
- 코인: 여러 번 던지기(부우부 3번). 결과는 게임판과 폰에 동시에 표시.
- 패 장수 제한 없음 (패 20장 이상 UI 고려).

## 5. 카드 효과 처리 — 자동과 수동의 경계

### 5.1 분류
| 분류 | 내용 | 처리 |
|---|---|---|
| **A. 계속·수정형** | 최대 HP, 데미지 보정, 약점 변경, 비용·후퇴 변경, 벤치 칸 수, 사이드 장수, 특성·도구·아이템·ACE SPEC 잠금, "다음 턴 기술 불가/도망 불가", 테라스탈 | **처음부터 자동** — 엔진이 모르면 판정이 틀려지고 수동으로 고칠 수 없음 |
| **B. 1회성 조작형** | 드로우, 서치, 교체, 에너지 붙이기·옮기기, 카운터 올리기·옮기기, 회복, 덱 위·아래 조작 | 자동화 전까지 **수동 도구**로 처리 가능 |
| **C. 가변 데미지 기술** | ×, +, 조건부 실패 | 자동화 전까지 **선언 시 데미지 입력 요청** (계산식 안내 표시) |

### 5.2 수동 도구와 권한
- 수동 도구: 드로우 N장, 덱에서 찾기(덱 열람), 트래쉬에서 가져오기, 덱 위·아래 N장 보기/놓기, 셔플, 에너지 붙이기·옮기기·트래쉬, 데미지 카운터 ±, 교체, 회복, 코인.
- **불변식은 수동에서도 유지**: 플레이어당 60장 보존, 카드는 구역 사이 이동만(생성·소멸 없음).
- 수동 조작도 턴 플래그에 반영 여부를 선택해야 한다 (예: 수동으로 붙인 에너지가 "턴당 1번"을 쓰는지) → 도구마다 기본값 지정.
- 권한 (15장 D16):
  | 조작 | 승인 |
  |---|---|
  | 공개 정보만 바꾸는 조작 (교체, 에너지 이동, 카운터) | 로그만 |
  | 비공개 정보 열람 (덱 찾기, 덱 위 보기) | 로그 + 자동화된 카드 사용 중일 때만, 그 외는 상대 승인 |
  | 엔진 판정 수정 (HP 보정, 기절 취소, 사이드 장수 수정, 비용 무시) | **상대 폰에서 승인** |
- 비턴 플레이어도 자신의 유발 효과를 처리할 수 있어야 한다.
- 수동 조작 뒤에도 기절 루틴(4.7)을 돌린다.
- 카드마다 "자동화됨/수동" 표시를 폰과 게임판에 보여준다.

### 5.3 자동화 우선순위 (수동 처리 불가·위험도 순)
1. A형 전부 (6.3의 계속 효과 카드)
2. C형 가변 데미지와 기술 효과
3. 덱 서치류 (수동이면 덱 전체 열람이 필요하므로)
4. 단순 드로우·교체

### 5.4 효과 구현 방식
- **효과 프리미티브**(서치, 드로우, 교체, 붙이기, 카운터 이동, 데미지 수정자, 유발, 방지·대체, 지속 시간)를 먼저 만들고, 카드는 프리미티브 조합으로 기술한다.
- 효과 처리 중 선택이 필요하면 **명시적 효과 스택**에 멈춰서 선택 요청을 보낸다 (직렬화 가능, 재접속·복원 가능). 제너레이터는 쓰지 않는다.

- 손에서 진화시켰을 때: 리자몽 ex(덱에서 기본 에너지 3장 붙이기), 야부엉(테라스탈이 있으면 트레이너스 2장 서치)
- 손에서 벤치에 냈을 때: 루차불(상대 벤치 2마리에 카운터 1개씩)
- 손에서 붙였을 때: 제트 에너지
- 기절할 때: 학습장치(에너지 옮기기), 피카츄 ex
- 차례 끝: 기술머신 에볼루션 트래쉬

### 6.4 가변 데미지 기술 (C형)
부우부(코인 3번 ×10), 리피아 ex(상대 에너지 수 ×60), 테라파고스 ex(벤치 수 ×30), 리자몽 ex(상대가 가져간 사이드 ×30 추가), 타부자고 ex(패의 기본 에너지 트래쉬 ×50), 우렁찬꼬리(자기 카운터 수 ×20), 메가디안시 ex(에너지 트래쉬 ×120), 릴리에의 삐삐 ex(양쪽 벤치 수 ×20 추가), 전툴라(번개 에너지면 +80), 메가입치트 ex(내가 가져간 사이드 ×80 / 상대에 카운터 있으면 30).

### 6.5 데이터 문제 (조사로 발견)
- 데이터 없음 2종: **밤의 들것(MC_643), 무쇠잎새 ex(SV5M_084)** — 일본판 대응을 못 찾음 → 수동 입력.
- 진화 전 이름 누락: 부스터 ex, 리피아 ex, 야부엉, 리자몽 ex, 피죤·피죤투 ex, 드래런치 등 다수 → 진화 계열 수동 보정.
- 문구 속 타입 아이콘 누락: "タイプの進化ポケモン"(게노세크트 ex), 파쪼옥의 에너지 타입, 릴리에의 삐삐 ex 약점 타입 등.
- 타입 오류 의심: 리자몽 ex SV3_134가 불꽃으로 나옴 (같은 카드 SV4a_349는 악 — 테라스탈 악이 맞음).
- 테라스탈·메가·미래(미라이돈 ex, 무쇠손 ex, 무쇠잎새 ex) 표시 없음 → 수동 지정.
- **한글 기술명·특성명이 없음** → 버튼·로그용 한글 데이터를 이미지 보고 입력·검수 (15장 D22).
- 결론: 자동 생성 결과를 **저장소에 고정**(`src/data/rules/cards.json`)하고, 120종을 카드 이미지와 **전수 대조**한 뒤 사용한다.

## 8. 웹 게임판 UI

### 8.1 레이아웃 모드 (로비에서 선택)
| 모드 | 화면 | 배치 |
|---|---|---|
| **마주 보기** | 테이블에 눕힌 모니터·태블릿 | 아래 절반 = 플레이어 1, 위 절반 = 플레이어 2 (**180° 회전**) |
| **나란히 보기** | 세워 둔 모니터·TV | 회전 없음, 위 = 플레이어 2, 아래 = 플레이어 1 |

눕힌 화면은 시야각이 좋은 IPS 패널이나 태블릿을 권장한다.

### 8.2 화면 구성 (마주 보기, 가로 16:9)
```
┌──────────────────────────────────────────────────────────────────────────┐
│ (180° 회전된 플레이어 2 진영)                                              │
│  [P2 상태줄: 턴·에너지✔·서포트○·후퇴○ / 패 6 · 덱 33 · 사이드 4]  (P2 방향) │
│  ┌덱┐┌트래쉬┐   [벤치 … 최대 8칸, 가변 폭]                 ┌사이드┐         │
│                          [ 배틀 포켓몬 ]                    └──────┘         │
├──────────── 가운데 띠: 방향 없는 요소만 ──────────────────────────────────┤
│        ◀ 차례 화살표 ▶     [스타디움]     (코인)     마지막 행동 1줄 ⇅       │
├──────────────────────────────────────────────────────────────────────────┤
│  ┌사이드┐                [ 배틀 포켓몬 ]                                    │
│  └──────┘   [벤치 … 최대 8칸, 가변 폭]                 ┌덱┐┌트래쉬┐         │
│  [P1 상태줄: 턴·에너지✔·서포트○·후퇴○ / 패 6 · 덱 31 · 사이드 5]  (P1 방향) │
└──────────────────────────────────────────────────────────────────────────┘
```
- **턴·횟수 상태는 각 진영 안에 각자 방향으로** 중복 표시. 가운데에는 방향 없는 요소(스타디움, 코인, 차례 화살표)만. 마지막 행동 한 줄은 양방향으로 두 번.
- 전체 로그는 폰의 로그 탭.
- 패는 뒷면 줄 대신 **숫자 배지 + 작은 부채꼴**.
- 사이드는 겹쳐 쌓고 숫자 표시.

### 8.3 포켓몬 칸 표시
- 1080p에서 카드 높이 약 200px → 카드 글자는 읽을 수 없으므로 **카드 밖 오버레이**로 표시:
  - 남은 HP 크게 / 최대 HP 작게 (데미지 카운터 수는 보조)
  - 붙은 에너지 아이콘, 도구 아이콘
  - **특수상태 배지** (색 + 아이콘 + 글자: 독·화상·잠듦·마비·혼란). 카드 회전은 쓰지 않음.
  - "이번 턴 나옴/진화함", "특성 사용함", "다음 턴 기술 불가", "도망 불가" 표시
  - 진화 단계 겹침
- 플레이어 효과(아이템 잠금 등)는 해당 진영 상태줄에 배지.
- 자동화되지 않은 카드는 작은 "수동" 표시.

### 8.4 카드 크게 보기
- 공개 카드를 누르면(터치 화면일 때) 같은 카드를 **좌우 2장, 각자 방향으로** 동시에 띄운다. 뒤집기 버튼은 보조로 둔다.
- 카드를 내거나 기술을 선언하면 게임판이 자동으로 **2~3초 스포트라이트**(양방향)를 띄운다 — 상대가 무엇을 썼는지 확인용.
- 포켓몬을 누르면 겹친 카드(진화 전, 에너지, 도구)를 넘겨 볼 수 있음. 트래쉬를 누르면 격자 목록.
- 터치가 없는 화면에서는 폰의 필드 탭에서 모든 공개 카드를 확대한다.

### 8.5 연출
- 이벤트는 순서 있는 묶음으로 받아 **큐로 재생**: 카드 이동, 데미지 숫자, 약점·저항력 계산 과정, 코인, 기절, 사이드.
- 연출 속도: 보통 / 빠르게 / 건너뛰기 (15장 D25).
- 브라우저 **전체 화면 + 화면 꺼짐 방지(Wake Lock)**.
- "누구의 어떤 입력을 기다리는 중"을 항상 표시.

| 패 | 10장 이하: 큰 카드 좌우 넘기기 + 아래 썸네일 줄 (기존 CardViewer 재사용). 10장 초과: 격자 |
| 필드 | 양쪽 필드 축소판. 포켓몬을 누르면 **그 포켓몬의 행동 메뉴**(특성, 기술, 후퇴, 확대). 모든 공개 카드 확대 가능 |
| 트래쉬 | [내 트래쉬 / 상대 트래쉬] 전환, 좌우 넘기기 또는 격자 (요청 사항) |
| 로그 | 전체 행동 기록 (내 시점으로 걸러진 것) |

### 9.2 조작
- 패의 카드 [사용하기]: 기본 포켓몬 → 벤치 / 진화 → 대상 / 에너지 → 대상 / 도구 → 대상 / 아이템·서포트·스타디움 → 사용. 대상은 필드 축소판에서 고른다.
- 쓸 수 없는 카드는 서버가 준 이유 표시 (예: "선공 첫 턴에는 서포트를 쓸 수 없습니다").
- 기술 버튼: **한글 기술명 + 데미지**, 에너지 조건을 만족한 것만 활성.
- **여러 단계 카드**(하이퍼볼: 2장 트래쉬 → 서치 → 선택)는 비용을 확정하기 전까지 [뒤로]·[취소] 가능.
- 기술, 턴 종료, 서포트는 **확인 단계**.
- 비공개 선택은 폰에서: 덱 서치(격자 + 가능한 대상 강조 + 종류별 정렬), 패에서 트래쉬할 카드, **사이드 고르기**(뒷면 6칸 중 위치), 멀리건 추가 드로우 수.
- 상대가 공개한 카드는 [확인]을 누를 때까지 표시.
- 상대 차례: 보기 전용. 나에게 선택이 필요하면(새 배틀 포켓몬 등) **진동 + 소리**.
- 요청에는 `afterEventSeq`가 붙어, 게임판 연출이 끝난 뒤에 폰에 뜬다.
- [수동 도구 ▸] 메뉴 (5.2), [항복].

### 9.3 기존 앱과의 연결
- 카드 확대·넘기기: `CardViewer` 재사용. 덱 선택: 기존 목록 + 인쇄 선택(`print_choice.json`).

| 정보 | 웹 게임판 | 본인 폰 | 상대 폰 |
|---|---|---|---|
| 필드, 트래쉬, 스타디움 | ✔ | ✔ | ✔ |
| 셋업 중 뒷면 포켓몬 | 뒷면 | ✔ | 뒷면 |
| 패 | 장수 | ✔ | 장수 |
| 덱 | 장수 | 서치·보기 중에만 | ✗ |
| 사이드 | 뒷면·장수 | 가져간 것만 | ✗ |
| 공개 효과(멀리건, 서치 공개) | ✔ (확인까지) | ✔ | ✔ |

누출 방지 규칙:
- **카드 개체 ID 재발급**: 카드가 비공개 구역(덱·패·사이드)에 들어갈 때 새 ID를 준다. 상대 시점에는 구역·순번만 보낸다.
- 스냅숏뿐 아니라 **이벤트와 로그 문자열도 시점별로 걸러서** 보낸다 (`draw` 이벤트에 카드 코드가 게임판으로 나가는 실수가 가장 흔함).
- 자동 **누출 테스트**: 모든 상태와 이벤트의 상대·게임판 시점을 직렬화해서 비공개 카드 코드가 없는지 검사 (12장).

## 11. 통신

- WebSocket JSON. 서버가 입력을 엔진으로 검증 → 상태 갱신 → 시점별 스냅숏 + 이벤트 묶음 전송.
- 클라이언트 → 서버: `hello{protocol, dataVersion, token?}`, `join`, `chooseDeck{deckId, prints}`, `ready`, `action{type, …}`, `choice{requestId, picks}`, `manual{…}`, `approve{requestId}`, `concede`
- 서버 → 클라이언트: `lobby`, `state{version, view, legalActions}`, `request{id, kind, options, cancellable, afterEventSeq}`, `events{seq, list}`, `error{reason}`
- **선택 요청 흐름**
  - 요청 스택: 효과 안의 효과
  - 비턴 플레이어 요청 (새 배틀 포켓몬 등), 양쪽 동시 요청 (셋업, 동시 기절 — 다음 턴 플레이어 먼저)
  - 재접속 시 미해결 요청 재전송, `requestId` 중복 제출 무시
  - 응답이 서버가 제시한 선택지 안에 있는지 검증
  - 취소는 비용을 내기 전까지만
- 연결 끊김: 수 초 유예 후 게임판에 "재접속 대기" + 게임 일시정지. 게임판(브라우저)이 끊겨도 서버 상태는 유지되고 새로고침으로 복구.
- UDP 알림: 서버가 1초마다 `{name, code, port, protocol}` 브로드캐스트.
