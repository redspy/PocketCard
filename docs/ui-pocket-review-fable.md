# 대전 화면 재설계 보고서 — Pocket 식 플레이 감각으로

조사는 글 자료(공략·리뷰·위키)만으로 했고, 스크린샷과 영상은 직접 보지 못했습니다. 그래서 조작 방식은 근거가 탄탄하지만, 화면 요소의 정확한 위치와 연출 세부는 상당 부분 추정입니다. 구현 전에 실제 게임 화면을 10분쯤 녹화해 2장의 "추정" 항목을 대조하는 것을 권합니다.

## 2. 대전 화면 분석

### 배치
- **확인:** 세로 화면에서 아래가 나, 위가 상대입니다. 각자 배틀 1칸과 벤치 3칸을 가집니다.
- **확인:** 패는 화면 맨 아래에 부채꼴로 펼쳐집니다. 덱은 오른쪽에 뒷면으로 놓이고, 트래쉬는 그 아래에 있습니다. 에너지 존은 오른쪽 아래입니다.
- **확인:** 스타디움은 낸 사람의 배틀필드 왼쪽에 놓입니다.
- **추정:** 상대 쪽은 내 쪽을 위아래로 뒤집은 대칭이고, 상대 패는 장수만 보이는 뒷면이며, 포인트는 양쪽 가장자리에 표시됩니다.
- **핵심:** 화면 전체가 하나의 "탁자"입니다. 탭이나 목록 전환 없이 모든 정보가 한 화면에 있고, 자세한 것만 탭·길게 누르기로 엽니다.

### 조작
| 행동 | 방식 | 근거 |
|---|---|---|
| 기본 포켓몬 내기 | 패에서 위로 끌어 빈 칸에 놓기 | 확인 |
| 진화 | 진화 카드를 대상 포켓몬 위에 놓기(대상은 초록 강조) | 확인 |
| 아이템·서포트 | 플레이매트 가운데로 끌기 | 확인 |
| 에너지 | 에너지 존의 토큰을 포켓몬 위로 끌기 | 확인 |
| 기술·특성·후퇴 | 포켓몬 탭 → 뜨는 버튼 탭 | 확인 |
| 후퇴 대상 | 벤치에서 탭해 선택 | 검색 요약 |
| 카드 상세 | 길게 누르기 | 확인 |
| 트래쉬·덱 | 더미 탭(목록 / 남은 장수) | 확인 |
| 턴 종료 | 버튼, 또는 공격하면 자동 종료 | 검색 요약 |
| 항복 | 메뉴에서 2단계 확인 | 확인 |

탭 → 탭만으로 카드를 낼 수 있는지는 확인하지 못했습니다.

### 피드백·연출
- **확인:** 지금 할 수 있는 것은 빛이 맥동하고, 놓을 수 없는 곳은 회색입니다. 잘못 놓으면 바로 안내가 뜹니다.
- **확인:** HP는 바와 남은 수치로 보이며 공격 뒤 자동으로 줄어듭니다. 상태이상은 카드 위에 표시됩니다.
- **확인:** 드로우·셔플·공격·효과마다 연출이 있습니다. 속도 조절이 없어 지루하다는 비판이 있습니다.
- **확인:** 선후공 코인은 자동입니다. 효과 코인은 플레이어가 튕기는 느낌으로 처리됩니다.
- **검색 요약:** 턴 90초, 총 20분 타이머가 있습니다. 화면 어디에 표시되는지는 모릅니다.
- **추정:** 데미지 숫자 팝업, 기절 연출, 차례 전환 배너의 구체적 모양.

### 흐름
- **확인:** 코인(자동) → 5장 드로우 → 배틀·벤치에 끌어 배치(리셋 가능) → 준비 완료 → 동시 공개 → 턴 진행 → 3점 또는 30턴에 종료.
- **확인:** 앱을 나갔다 오면 진행 중인 대전을 이어 하도록 묻습니다.
- **추정:** 기절 뒤 교체는 패널이 아니라 벤치 포켓몬을 직접 탭해 고릅니다(후퇴와 같은 방식).
- **참고:** 덱 서치가 없어서 "목록에서 카드 고르기" 화면이 거의 필요 없습니다. 우리와 가장 크게 다른 지점입니다.

## 3. 우리 룰과의 차이

| 항목 | Pocket | 우리(정식 룰) | 대안 |
|---|---|---|---|
| 벤치 | 3칸 | 5칸(최대 8) | 내 벤치 132px, 상대 벤치 104px로 한 줄 배치. 8칸이면 같은 줄을 81px로 줄이고 길게 누르기로 확대 |
| 승리 | 포인트 3 | 사이드 6장 | 배틀 줄 왼쪽에 사이드 더미(2×3 뒷면). 사이드 획득은 더미가 펼쳐지고 탭해 가져오는 연출 |
| 에너지 | 에너지 존 토큰 | 패의 에너지 카드 | 패에서 포켓몬 위로 끌기(진화와 같은 제스처). 오른쪽 아래 자리는 턴 종료 버튼과 "이번 턴 에너지·서포트·후퇴" 칩으로 사용 |
| 패 | 최대 10장 | 제한 없음(15장 이상도 흔함) | 겹침 폭이 자동으로 줄어드는 부채. 9장부터는 좌우로 훑기, 누른 카드만 위로 올라옴 |
| 덱 서치 | 없음 | 매우 많음 | 아래에서 올라오는 카드 고르기 시트(격자, 고를 수 있는 것만 보기 토글 유지). 유일하게 목록이 남는 곳 |
| 트레이너스 | 소수 | 다수 + 도구 + 스타디움 | 도구는 포켓몬 위에 놓기, 스타디움·아이템·서포트는 가운데에 놓기. 스타디움은 두 배틀 포켓몬 사이 가운데 줄에 가로 카드로 표시 |
| 특수 상태 | 일부 | 5종 | 잠듦·마비·혼란은 카드 기울임 + 배지, 독·화상은 마커 배지(실물 카드게임 관례) |
| 붙은 카드 | 에너지 아이콘 | 에너지 다수 + 도구 + 진화 밑 카드 | 슬롯 아래에 타입 색 점 줄(6개 초과는 "×N"), 도구는 옆 탭. 슬롯을 길게 누르면 붙은 카드 전체를 넘겨 봄(기존 `_slot_codes` 재사용) |
| 준비 | 코인 → 배치 | 멀리건, 선후공 선택, 사이드 깔기 | 같은 탁자 위에서 진행. 선후공은 작은 대화상자, 배치는 끌어 놓기 + 준비 완료 |
| 타이머 | 90초 / 20분 | AI 연습에는 불필요 | 넣지 않음. 턴 번호만 표시 |
| 대전 길이 | 5~10분 | 20분 이상, 효과 연쇄가 김 | **연출 속도 조절 필수**(기존 AI 속도 버튼을 연출 배속과 통합). Pocket이 비판받는 지점 |

## 4. 새 대전 화면 설계

기준은 720×1560입니다. `project.godot`의 뷰포트 높이는 1580이 아니라 1560이고, stretch는 canvas_items/expand입니다.

```
┌──────────────────────────────────────────┐
│ ☰   턴 7 · 내 차례                  ⏩ 속도 │ 상단 바 (safe_top + 56)
│ AI  패 ▮▮▮▮▮▮ 6                           │ 상대 패: 뒷면 + 장수 (48)
│  [b1] [b2] [b3] [b4] [b5]                │ 상대 벤치 104×146
│ ┌────┐      ┌────────┐       ┌──┐        │
│ │사이드│      │ 상대   │       │덱 │ 41     │ 상대 배틀 170×238
│ │▮▮▮ │      │ 배틀   │       ├──┤        │ 왼쪽 사이드, 오른쪽 덱·트래쉬
│ │▮▮▮ │      │ 90/120 │       │트 │ 9      │
│ └────┘      └────────┘       └──┘        │
│ ─ ─ ─ ─ ─ [ 스타디움 (가로 카드) ] ─ ─ ─ ─ ─ │ 가운데 줄 = 트레이너스 드롭 구역 (56)
│ ┌────┐      ┌────────┐       ┌──┐        │
│ │사이드│      │  내    │       │덱 │ 38     │ 내 배틀 200×280
│ │▮▮▮ │      │ 배틀   │       ├──┤        │ 탭하면 옆에 기술·특성·후퇴 버튼
│ │▮▮  │      │130/180 │       │트 │ 12     │
│ └────┘      └─●●●─◆─┘       └──┘        │ ● 에너지 점, ◆ 도구 탭
```

높이 합계는 약 1,310px이고 250px쯤 여유가 있어 작은 화면에서도 스크롤이 없습니다. 현재 화면의 탭(패·필드·트래쉬·로그), 행동 버튼 줄, "최근 AI 행동" 줄은 없어집니다.

- 필드는 항상 보입니다.
- 트래쉬는 더미를 탭하면 시트로 열립니다(내 것, 상대 것 모두).
- 로그와 항복은 ☰ 메뉴에 들어갑니다.
- AI 행동은 탁자 위의 카드 이동으로 직접 보입니다.

### 따르는 것과 따르지 않는 것

| 따른다 (배치·상호작용 패턴) | 따르지 않는다 (고유 표현) |
|---|---|
| 위아래 대칭 탁자, 패는 아래 부채, 덱·트래쉬는 오른쪽 | 플레이매트 배경, 테두리 장식, 칸 모양 |
| 끌어 놓기, 탭 후 버튼, 길게 누르기로 상세 | 버튼·아이콘 그림, 글꼴, 색 구성 |
| 가능한 것은 맥동, 불가는 흐리게, 실패 시 즉시 안내 | 맥동의 색·모양(우리는 `UI.ACCENT` 금색 테두리) |
| HP 바 + 수치, 순차 연출, 차례 배너 | 공격 이펙트, 코인 디자인, 배너 디자인, 효과음 전부 |
| 준비 → 동시 공개 → 결과 흐름 | 에너지 존, 포인트 표시, 스탬프, 타이머 UI |

배경은 지금의 `UI.BG`, `UI.BG_DEEP` 단색 계열과 `UI.box()` 둥근 패널을 유지합니다. 타입 표시는 공식 에너지 심볼 대신 색 점과 한 글자(불·물 등)로 합니다. 효과음은 자체 제작하거나 CC0만 씁니다.

## 5. 조작·연출 설계

### 조작
엔진의 `legalMoves`가 이미 `{kind, card, target(sid), input}`을 주므로, 끌어 놓기는 **card + target이 일치하는 행동을 찾아 보내기**로 그대로 대응됩니다.

- **끌기 시작:** 패 카드를 위로 14px 이상 움직이면 끌기입니다. 옆으로 움직이면 패 훑기입니다. 그 카드의 행동이 가진 `target` 슬롯들이 맥동하고 나머지는 어두워집니다.
- **놓기:**
  - `target` 있는 행동(진화·에너지·도구·이상한사탕)은 해당 포켓몬 위에 놓습니다.
  - `target` 없는 행동(벤치에 내기·아이템·서포트·스타디움)은 패 영역 위쪽 아무 데나 놓습니다. 기본 포켓몬은 벤치 줄이 강조됩니다.
  - 무효한 곳에 놓으면 카드가 패로 되돌아가고 이유가 한 줄로 뜹니다.
- **탭 대안:** 카드 탭 → 카드가 올라오고 대상이 맥동 → 대상 탭으로 같은 결과를 냅니다. 끌기가 불편한 사용자와 자동 테스트를 위해 필수입니다. 기존 "위로 밀기 = 사용"은 끌기에 흡수됩니다.
- **포켓몬 탭:** 카드 옆에 말풍선 메뉴가 뜹니다.
  - 기술마다 이름·비용 점·데미지를 보여 줍니다. 쓸 수 없으면 흐리게 하고 이유를 적습니다.
  - 특성과 후퇴(비용 표시)도 여기에 있습니다. 벤치 포켓몬은 특성만 보입니다.
- **선택 요청:** 기존 `_request_panel`의 종류 구분(slots / cards / prizes / values)을 그대로 씁니다.
  - `slots`: 패널 없이 탁자에서 직접 고릅니다. 위쪽에 안내 띠가 뜨고 후보가 맥동합니다. 여러 개를 고를 때는 "결정" 버튼이 나옵니다.
  - `cards`: 아래 시트의 격자에서 고릅니다.
  - `prizes`: 사이드 더미가 펼쳐집니다.
  - `values`: 가운데 작은 대화상자입니다.
  - `ackReveal`: 공개된 카드가 가운데에 뜨고 탭하면 닫힙니다.
- **길게 누르기:** 어디서든 크게 보기입니다. 기존 `_zoom_list`와 좌우 넘기기를 유지합니다.
- **턴 종료:** 할 수 있는 행동이 남아 있으면 기존 2단계 확인을 유지합니다. 남은 행동이 없으면 버튼이 맥동합니다.

### 연출 (기본 속도, ⏩로 1×·2×·즉시)
| 사건 (`events_log`) | 연출 | 시간 |
|---|---|---|
| 드로우 | 덱에서 패로 카드가 날아옴(상대는 뒷면) | 0.25s |
| play | 패에서 가운데에 크게 0.5s 머문 뒤 트래쉬나 슬롯으로 이동. 상대 카드도 같아서 스포트라이트 상자를 대체 | 0.7s |
| attack | 공격 카드가 앞으로 돌진, 기술 이름 띠, 대상 흔들림 | 0.5s |
| damage / heal | 숫자가 튀어오르고 HP 바가 줄어듦 | 0.4s |
| condition | 배지가 튀어나오고 카드가 기울어짐 | 0.2s |
| ko | 카드가 회색으로 변해 트래쉬로 이동하고 붙은 카드가 뒤따름. 이어서 사이드 선택 | 0.6s |
| coin | 자체 디자인 원판 뒤집기, 결과 글자. 여러 번이면 줄지어 빠르게 | 0.6s |
| turnStart | 가운데 배너(기존 `_show_banner`) | 0.8s |
| gameEnd | 결과 패널(승패, 이유, 다시 하기, 로그) | — |

원칙은 세 가지입니다.
- 입력은 연출을 기다리지 않습니다. 내 행동은 즉시 반영되고 연출은 따라옵니다.
- 화면을 탭하면 현재 연출을 건너뜁니다.
- 연출 중에는 `Input.vibrate_handheld`로 짧은 진동을 줍니다(KO 30ms, 놓기 10ms).

## 6. 구현 구조와 단계

### 노드 구성
새 파일로 만들고 기존 `game_screen.gd`(1,160줄)는 LAN 모드와 대체용으로 남깁니다. LAN 모드는 게임판 화면이 따로 있으므로 이번 설계는 AI 연습(`Net.solo`)에 먼저 적용합니다.

```
BattleScreen (Control)            screens/battle_screen.gd — Net.changed 수신, 조립만
├─ Board (Control)                battle/board.gd — 슬롯·더미 배치
│   ├─ SlotView × N               battle/slot_view.gd — sid 로 유지(다시 만들지 않음)
│   ├─ PileView (덱/트래쉬/사이드) × 6
│   └─ StadiumView, OppHandView
├─ HandFan (Control)              battle/hand_fan.gd — iid 로 CardView 유지, 부채 배치
├─ HudLayer                       상단 바, 턴 종료, 칩, 포켓몬 행동 말풍선, 안내 띠
├─ SheetLayer                     카드 고르기, 트래쉬, 로그 시트, 크게 보기
├─ FxLayer (mouse IGNORE)         날아가는 카드, 숫자, 코인, 배너
└─ DragLayer                      끌고 있는 카드
battle/layout.gd   — static func compute(size, bench_max, hand_n) -> {이름: Rect2}  (순수 함수)
battle/fx_queue.gd — 사건을 순서대로 재생, speed 배율, skip()
```

### 핵심 결정
- **유지형 노드:** 지금은 내용이 바뀌면 부분을 통째로 다시 만듭니다(`_built` 키 비교). 새 화면은 iid·sid로 노드를 유지하고 달라진 것만 Tween으로 옮깁니다. 그래야 카드가 "이동"합니다.
- **끌어 놓기는 직접 구현:** Godot 내장 `_get_drag_data`는 쓰지 않습니다. 들어 올림·기울임·되돌아감 제어가 어렵고 터치에서 미리보기가 제한적이기 때문입니다.
  - `TapArea`에 `drag_started / dragged / drag_ended` 신호를 추가합니다.
  - 카드를 DragLayer로 옮겨 손가락을 따라가게 하고, 놓을 때 `SlotView.get_global_rect()`로 판정합니다.
  - 패는 ScrollContainer가 아닌 자체 배치로 만들어 스크롤과 끌기의 충돌을 없앱니다.
- **연출과 상태의 시차:** `view`는 최종 상태로 한 번에 오고 사건은 `seq` 순서로 옵니다. FxQueue가 재생 중일 때 SlotView는 "아직 재생 안 된 damage 합"만큼 HP를 덜 깎아 보여 주고, 큐가 비면 view와 일치시킵니다.
  - 이를 위해 damage·ko·condition 사건에 대상 sid가 있어야 합니다. 있는지는 확인하지 못했습니다.
  - 없으면 TS 엔진과 GDScript 포팅 양쪽에 추가해야 하고, `g_compare`의 동등성도 유지해야 합니다.
- **화면 크기:** 모든 위치는 `layout.gd` 한 곳에서 `size`와 safe area로 계산하고 `resized`에 다시 계산합니다. 화면 비율이 18:9보다 짧으면 패 부채 높이를 먼저 줄이고, 그다음 상대 벤치를 줄입니다. 태블릿은 폭을 720 기준으로 제한하고 가운데 정렬합니다.

### 단계 (각 단계가 끝나면 플레이 가능)
1. `layout.gd` 순수 함수와 빈 칸만 그리는 BattleScreen을 만듭니다. 설정 토글로 새 화면과 기존 화면을 전환합니다.
2. SlotView(카드, HP 바·수치, 에너지 점, 도구, 상태 배지)와 PileView·상대 패를 만듭니다. 아직 조작은 없고 아래에 기존 패·버튼을 임시로 둡니다.
3. HandFan을 만듭니다. 탭 선택, 길게 누르기, 가능·불가 표시를 넣습니다.
4. 포켓몬 탭 말풍선(기술·특성·후퇴)을 넣고 행동 버튼 줄을 없앱니다.
5. 탭 → 대상 탭 방식(card + target 대응)을 넣고 패 아래 행동 버튼을 없앱니다.
6. 끌어 놓기를 넣습니다.
7. 선택 요청을 옮깁니다. slots는 탁자에서, cards는 시트에서, prizes는 사이드 더미에서, values는 대화상자로 처리합니다.
8. 트래쉬·로그 시트와 ☰ 메뉴를 넣고 탭을 없앱니다.
9. FxQueue를 붙입니다. 드로우·play 이동과 배너부터 시작해 damage·HP, KO, 코인 순으로 넣고 속도·건너뛰기를 붙입니다.
10. 준비 단계(끌어 배치, 준비 완료)와 결과 패널을 만듭니다.
11. 벤치 8칸, 진동·효과음, 작은 화면과 태블릿 대응으로 다듬습니다.

## 7. 위험과 우선순위

| 위험 | 영향 | 대응 |
|---|---|---|
| 연출이 길어 대전이 늘어짐(정식 룰은 효과 연쇄가 김) | 높음 | 배속과 탭 건너뛰기를 9단계 시작부터 포함. AI 턴은 묶어서 재생 |
| view와 사건의 시차로 HP가 먼저 줄어 보임 | 중간 | 표시 보정 방식. 사건에 sid가 없으면 엔진 수정 필요(TS·GD 양쪽) |
| 끌기와 패 훑기·길게 누르기의 판정 충돌 | 중간 | 방향과 14px 문턱으로 분기. 탭 대안은 항상 유지. 실기기 확인 필수 |
| 5~8칸 벤치와 큰 패에서 카드가 작아 읽기 어려움 | 중간 | 읽는 것은 길게 누르기로 넘기고, 탁자는 "상태 파악용"으로 HP·에너지만 크게 |
| 다시 그리기에서 유지형 노드로 바꾸며 생기는 불일치 버그 | 중간 | "큐가 비면 화면 == view" 불변식을 자동 검사 |
| Pocket과 지나치게 닮아 보임 | 낮음~중간 | 4장의 경계표 준수. 고유 요소(사이드 더미, 턴 칩, 카드 기울임)를 눈에 띄게 |
| 추정에 기대어 설계한 부분(상대 쪽 배치, 팝업 모양) | 낮음 | 구현 전 실제 화면 녹화로 대조 |

**우선순위:** 체감 변화의 대부분은 1~6단계(한 화면 탁자와 끌어 놓기)에서 나옵니다. 7~8단계는 목록 UI를 없애는 마무리입니다. 9단계는 가장 "게임처럼" 보이게 하지만 위험도 가장 커서, 앞 단계가 안정된 뒤에 합니다.

**검증:**
- **자동(헤드리스):** `layout.gd`를 화면 크기 5종 × 벤치 5·8칸 × 패 1~20장으로 돌려, 칸이 겹치지 않고 화면 밖으로 나가지 않으며 터치 영역이 최소 80px인지 단언합니다.
- **자동(UI 봇):** `scripts/ui-bot.mjs`의 Godot 판을 만듭니다. 고정 시드로 BattleScreen의 의미 단위 함수(`tap_card(iid)`, `drop(iid, sid)`, `pick(option)`)를 호출해 AI와 끝까지 여러 판 플레이하고, 오류가 없는지, 게임이 종료되는지, 불변식이 지켜지는지 확인합니다. 연출은 "즉시" 속도로 둡니다.
- **자동(입력 수준):** `Input.parse_input_event`로 터치·끌기 사건을 합성해 끌어 놓기 판정을 몇 가지 시나리오로 확인합니다.
- **반자동:** 창 모드에서 정해진 장면의 뷰포트를 PNG로 저장해 눈으로 비교합니다. 헤드리스는 렌더러가 없어 캡처가 안 됩니다.
- **수동만 가능:** 끌기의 손맛, 연출 타이밍, 진동은 실기기에서 단계마다 한 판씩 해 봐야 합니다.
