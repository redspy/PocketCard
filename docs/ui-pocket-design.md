# 폰 대전 화면 재설계 — 모바일 카드게임식 "탁자" 화면 (종합안)

TCG Pocket 대전 화면을 웹으로 조사하고(Claude), 같은 지시를 Fable 헤드리스에 내려 따로 분석한 뒤(`ui-pocket-review-fable.md`) 두 결과를 합친 설계다.

**경계:** 배치·조작·진행 흐름·연출 타이밍·정보 구조는 최대한 같은 감각으로 맞춘다.
그 게임 고유의 그래픽 자산(아이콘, 플레이매트 배경, 버튼 그림, 로고, 효과음)과 고유 시각 디자인은 베끼지 않고
우리 앱 스타일(`UI.BG`·`UI.ACCENT` 금색·둥근 패널)로 만든다.

## 2. 정식 룰이라 그대로 못 가져오는 것

| 항목 | 그 게임 | 우리 | 대안 |
|---|---|---|---|
| 벤치 | 3칸 | 5칸(제로의 대공동이면 8) | 한 줄, 칸 수에 맞춰 카드 폭 자동 축소 (내 132px / 상대 104px, 8칸이면 81px) |
| 승리 | 포인트 3 | 사이드 6장 | 배틀 칸 왼쪽에 사이드 더미(2×3 뒷면), 가져올 때 더미가 펼쳐지고 탭 |
| 에너지 | 에너지 존 토큰 | 패의 에너지 카드 | **진화와 같은 제스처**(패 → 포켓몬 위로 끌기). 오른쪽 아래는 턴 종료 + "이번 턴 에너지·서포트·후퇴" 칩 |
| 패 | 최대 10장 | 제한 없음 | 장수에 따라 겹침 자동 조절, 9장 이상은 좌우로 훑기 |
| 덱 서치 | 없음 | 매우 많음 | 아래에서 올라오는 **카드 고르기 시트**(격자, "고를 수 있는 카드만" 토글 유지) — 목록이 남는 유일한 곳 |
| 트레이너스 | 소수 | 다수 + 도구 + 스타디움 | 도구는 포켓몬 위, 아이템·서포트·스타디움은 가운데 줄. 스타디움은 두 배틀 칸 사이 가운데 줄에 가로로 |
| 특수상태 | 일부 | 5종 | 잠듦·마비·혼란은 카드 기울임 + 배지(실물 관례), 독·화상은 마커 배지 |
| 붙은 카드 | 에너지 아이콘 | 에너지 여러 장 + 도구 + 진화 전 카드 | 카드 아래 타입 색 점 줄(6개 넘으면 ×N) + 도구 탭. 길게 누르면 지금의 "붙은 카드 넘겨 보기" |
| 대전 길이 | 5~10분 | 20분 이상, 효과 연쇄가 김 | **연출 배속(1×·2×·즉시) + 탭으로 건너뛰기 필수** — 그 게임이 비판받는 지점을 피한다 |

## 4. 조작

엔진의 `legalMoves` 가 이미 `{kind, card, target(sid), input}` 을 주므로 **"끌어서 놓은 카드 + 놓은 포켓몬"에 맞는 행동을 찾아 보내면** 된다 (규칙 엔진 변경 없음).

- **끌기:** 패 카드를 위로 14px 이상 움직이면 끌기, 옆이면 패 훑기. 끄는 동안 그 카드의 대상 칸이 맥동하고 나머지는 흐려진다.
  - 대상이 있는 행동(진화·에너지·도구·이상한사탕)은 그 포켓몬 위에 놓는다.
  - 대상이 없는 행동(벤치에 내기·아이템·서포트·스타디움)은 탁자 위 아무 데나 놓는다. 기본 포켓몬은 빈 벤치 칸이 강조된다.
  - 못 놓는 곳이면 카드가 패로 돌아가고 이유를 한 줄로 보여 준다.
- **탭 대안(필수):** 카드 탭 → 카드가 올라오고 대상이 맥동 → 대상 탭. 끌기가 불편한 사람과 자동 테스트용. 지금의 "위로 밀기 = 사용"은 끌기에 흡수.
- **포켓몬 탭 → 말풍선:** 기술마다 이름·비용 점·데미지(**약점이 맞으면 ×2 표시**)를 보여 주고, 못 쓰면 흐리게 + 이유. 특성과 후퇴(비용)도 여기. 벤치는 특성만.
- **선택 요청:** 기존 종류 구분을 그대로 쓴다.
  - 포켓몬 고르기 → 패널 없이 탁자에서 직접 탭 (위에 안내 띠, 후보 맥동, 여러 개면 "결정")
  - 카드 고르기 → 아래 시트 격자 / 사이드 → 사이드 더미가 펼쳐짐 / 값(예·아니오 등) → 가운데 작은 대화상자 / 공개 확인 → 가운데에 카드, 탭하면 닫힘
- **길게 누르기:** 어디서든 크게 보기 (지금의 넘겨 보기·붙은 카드 줄 유지).
- **턴 종료:** 할 수 있는 행동이 없으면 버튼이 맥동. 남아 있으면 지금처럼 두 번 누르기 확인.
- **자동 진행(🤖):** 켜면 내 차례도 AI(GBot)가 둔다. 그 게임의 Auto 와 같은 역할 + 자동 테스트에도 쓴다.

## 5. 연출 (기본 1×, ⏩ 로 2×·즉시, 화면 탭 = 지금 연출 건너뛰기)

| 사건 | 연출 | 시간(1×) |
|---|---|---|
| 드로우 | 덱에서 패로 카드가 날아옴 (상대는 뒷면) | 0.25s |
| 카드 사용(play) | 가운데에 크게 잠깐 → 트래쉬나 칸으로 이동 (지금의 스포트라이트 상자 대체) | 0.7s |
| 기술(attack) | 공격 카드가 앞으로 돌진 + 기술 이름 띠 + 대상 흔들림 | 0.5s |
| 데미지·회복 | 숫자 튀어오름 + HP 바 감소 | 0.4s |
| 특수상태 | 배지 튀어나옴 + 카드 기울임 | 0.2s |
| 기절 | 카드가 회색 → 트래쉬로, 붙은 카드가 뒤따름 → 사이드 가져오기 | 0.6s |
| 코인 | 자체 디자인 원판 뒤집기 + 결과 글자 | 0.6s |
| 차례 전환 | 가운데 배너 (지금의 `_show_banner`) | 0.8s |
| 게임 끝 | 결과 패널 (승패·이유·다시 하기·로그) | — |

원칙: 입력은 연출을 기다리지 않는다(상태는 즉시 반영, 연출은 뒤따름). 진동은 놓기 10ms, 기절 30ms.

**연출과 상태의 시차:** 상태(view)는 최종값으로 한 번에 오고 사건은 순서대로 온다. 연출이 남아 있는 동안 HP 는 "아직 재생 안 된 데미지 합"만큼 덜 깎아 보여 주고, 연출이 끝나면 view 와 맞춘다.
- 데미지·회복·특수상태 사건에는 대상 `sid` 가 있다 (확인함). **기절(ko) 사건에는 없다** → TS 엔진과 GDScript 엔진 **양쪽에 `sid` 추가**, 엔진 비교 테스트로 일치 확인.

## 6. 구현 구조

```
BattleScreen (screens/battle_screen.gd)   — Net.changed 수신, 조립만. 기존 game_screen.gd 는 LAN 대전용으로 유지
├─ Board        battle/board.gd           — 칸·더미 배치
│   ├─ SlotView × N   battle/slot_view.gd — sid 로 유지 (다시 만들지 않음 → 카드가 "이동"함)
│   ├─ PileView (덱·트래쉬·사이드) × 6
│   └─ StadiumView, OppHandView
├─ HandFan      battle/hand_fan.gd        — iid 로 카드 유지, 부채 배치 (ScrollContainer 대신 직접 배치 → 끌기와 충돌 없음)
├─ HudLayer     상단 바, 턴 종료, 칩, 기술 말풍선, 안내 띠
├─ SheetLayer   카드 고르기, 트래쉬, 로그, 크게 보기
├─ FxLayer      날아가는 카드·숫자·코인·배너 (누름 통과)
└─ DragLayer    끌고 있는 카드
battle/layout.gd    static compute(size, bench_max, hand_n) -> {이름: Rect2}  — 순수 함수 (자동 테스트 대상)
battle/fx_queue.gd  사건 순서 재생, 배속, 건너뛰기
```

- 끌어 놓기는 Godot 내장 드래그 대신 직접 구현: `TapArea` 에 `drag_started / dragged / drag_ended` 신호 추가, 놓을 때 `SlotView.get_global_rect()` 로 판정.
- 모든 위치는 `layout.gd` 한 곳에서 화면 크기·안전 영역으로 계산. 화면이 짧으면 패 높이 → 상대 벤치 순으로 줄이고, 태블릿은 폭 720 기준 가운데 정렬.

## 7. 단계 (각 단계 끝마다 플레이 가능, AI 연습에 먼저 적용)

1. `layout.gd` + 빈 칸만 그리는 BattleScreen. 설정 토글로 새 화면 ↔ 기존 화면.
2. SlotView(카드·HP 바·에너지 점·도구·상태 배지·약점 배지), 더미, 상대 패. 아래에 기존 패·버튼 임시 유지.
3. HandFan: 탭 선택, 길게 누르기, 쓸 수 있음/없음 표시.
4. 포켓몬 탭 말풍선(기술·특성·후퇴) → 행동 버튼 줄 제거.
5. 탭 → 대상 탭 → 패 아래 행동 버튼 제거.
6. 끌어 놓기.
7. 선택 요청을 탁자·시트·사이드 더미·대화상자로.
8. 트래쉬·로그 시트, ☰ 메뉴 → 탭 제거.
9. FxQueue: 드로우·사용 이동·배너 → 데미지·HP → 기절 → 코인, 배속·건너뛰기. (ko 사건 sid 추가 포함)
10. 준비 단계(끌어 배치·준비 완료), 결과 패널, 자동 진행 🤖.
11. 벤치 8칸, 진동, 작은 화면·태블릿.

체감 변화의 대부분은 1~6단계(한 화면 탁자 + 끌어 놓기). 9단계가 가장 "게임처럼" 보이지만 위험도 가장 커서 앞 단계가 안정된 뒤에 한다.

## 8. 검증

- **자동:** `layout.gd` 를 화면 5종 × 벤치 5·8칸 × 패 1~20장으로 돌려 겹침·화면 밖·터치 영역(최소 80px) 단언.
- **자동:** 자동 진행(🤖) + "즉시" 배속으로 BattleScreen 을 끝까지 여러 판 — 오류 없음, 게임 종료, "연출이 끝나면 화면 == view" 불변식.
- **자동:** `Input.parse_input_event` 로 끌기·탭 합성 (지금의 solotest 방식 확장).
- **창 모드 캡처:** 정해진 장면을 PNG 로 저장해 눈으로 비교.
- **실기기만 가능:** 끌기 손맛, 연출 타이밍, 진동 — 단계마다 한 판씩.

# 개정 (v2) — 모드별 적용: AI 연습 = 탁자, 서버 대전 = 개인 손패

**원칙:** 서버(게임판) 대전에서는 "게임판(필드·연출)은 웹, 폰은 비공개 손패와 내 조작"이라는 처음 콘셉트를 그대로 지킨다.
탁자 화면(위 1~9장)은 **AI 연습(게임판 없음)** 에만 쓴다.

| 요소 | AI 연습 (탁자 모드) | 서버 대전 (손패 모드) |
|---|---|---|
| 상대 필드·상대 벤치·사이드 더미 | 탁자에 늘 표시 | **없음** (웹 게임판이 보여줌) |
| 내 필드 | 탁자 아래 절반 (크게) | **작은 "내 포켓몬" 줄** — 끌어 놓기 대상·기술 말풍선 열기용 |
| 손패 | 아래 부채, 끌어 놓기·탭 대상 | 같음 (부채를 더 크게: 화면의 주인공) |
| 기술·특성·후퇴 | 내 배틀 포켓몬 탭 → 말풍선 | 같음 (작은 줄의 배틀 포켓몬 탭) |
| 선택 요청 | 포켓몬 고르기는 탁자에서 직접, 카드는 시트 | **모두 시트** (포켓몬 고르기 시트에 양쪽 필드를 작게 — 상대 포켓몬을 고르는 효과 때문) |
| 연출 | 전체 (드로우·이동·데미지·기절·코인·배너) | **최소** — 내 행동 확인 진동, 차례 배너, 상대 행동은 한 줄 알림 (큰 연출은 웹 게임판) |
| 상단 바 | ☰ · 턴 · 배속 · 🤖 자동 | ☰ · 턴 · 상태(재접속 등). 배속·자동 없음 |
| 트래쉬·로그·항복 | ☰ 메뉴 / 더미 탭 | ☰ 메뉴 (내·상대 트래쉬 시트, 로그, 항복) |

구현은 한 화면(`BattleScreen`)에 `mode = "table" | "hand"` 를 두고 부품(손패 부채, 포켓몬 칸, 말풍선, 시트, 연출 큐)을 함께 쓴다.
`Net.solo` 이면 탁자, 아니면 손패. 기존 `game_screen.gd` 는 설정 토글로 남겨 두는 대체 화면.

### 단계 (v2, 각 단계 = 테스트 통과 → 커밋·푸시)
1. 배치 계산(`layout.gd`, 두 모드) + 탁자 그리기(포켓몬 칸·더미·상대 패·스타디움·상단 바) — 배치 단언 테스트, 실제 게임 화면 그리기 테스트
2. 손패 부채 + 탭 선택·길게 누르기 + 탭→대상 탭으로 쓰기 + 기술 말풍선 + 턴 종료 → 탁자로 끝까지 플레이 가능 — UI 함수로 AI 와 끝까지 대전하는 자동 테스트
3. 끌어 놓기 — 합성 터치로 끌기 시나리오 테스트
4. 선택 요청 (탁자 고르기·카드 시트·사이드·값 대화상자·공개 확인) — 자동 대전 테스트(요청 포함)
5. ☰ 메뉴(로그·트래쉬·항복 2단계), 🤖 자동 진행, 배속 → AI 연습 기본 화면을 새 화면으로
6. 연출 큐(드로우·사용 이동·데미지 숫자·HP 지연 표시·기절·코인·공격 돌진·배너, 배속·건너뛰기) + 기절 사건 sid (TS·GD 엔진 같이, 엔진 비교 테스트) — "연출이 끝나면 화면 == 상태" 불변식 테스트
7. 준비 단계·결과 패널
8. 서버 대전 손패 모드 — 서버 + 웹 없는 봇 상대(LAN 봇 스크립트)로 앱이 끝까지 대전하는 테스트
9. 마무리: 벤치 8칸, 작은 화면·태블릿 배치 테스트, 진동, APK

## 진행 기록 (v2)
- **1단계 완료** — `battle/layout.gd`(두 모드 배치, 화면 5종 × 벤치 5·8칸 30가지 단언 통과), `battle/slot_view.gd`(HP 숫자·막대, 에너지 점, 도구, 특수상태 기울임·배지, 배틀 포켓몬 약점·저항 상시 표시), `battle/pile_view.gd`, `screens/battle_screen.gd`(그리기). 테스트: 오프라인 게임 한 판을 끝까지 두며 탁자·손패 화면이 매 순간 상태와 일치(칸 수·위치·HP·덱·트래쉬·사이드). `sh scripts/godot-ui-tests.sh` (npm test 에도 포함).
- **2단계 완료** — `battle/hand_fan.gd`(부채꼴 손패, iid 유지, 고른 카드 올림, 많으면 옆으로 넘기기), `battle/zoom.gd`(어디서나 크게 보기), `battle/request_sheet.gd`(기본 선택 시트), 화면 조작: 손패 탭 → 대상 맥동 → 대상 탭 / 위로 밀기 = 바로 사용 / 내 포켓몬 탭 → 기술(비용·데미지·약점 ×2 표시, 못 쓰면 흐리게)·특성·후퇴 말풍선 / 턴 종료(남은 행동 있으면 두 번) / 스타디움 효과 버튼. 테스트: AI 가 고른 수를 **화면 조작으로만** 실행해 탁자·손패 모드 각각 끝까지 대전, 보낸 입력 = 고른 입력 확인 (2회 연속 통과). 고친 것: 스타디움이 떠나 벤치가 잠시 최대치보다 많을 때 6번째 포켓몬이 안 그려지던 문제, 사라진 카드에 늦게 온 이미지를 넣다 나던 오류.
- **3단계 완료** — 끌어 놓기: 손패 카드를 위(대각선 포함, 수직에서 약 70°까지)로 끌면 손가락을 따라오는 카드, 대상 위에서 커짐, 놓으면 그 행동 / 못 놓는 곳이면 돌아오고 놓을 수 있는 포켓몬 안내. 옆으로 밀면 패 넘기기, 카드가 많으면 겹침을 줄이다가(최소 44px) 넘기기. 테스트: **창 모드 합성 터치**로 실제 끌어 놓기만으로 탁자·손패 모드 끝까지 대전 + 잘못 놓기 검사 (헤드리스는 합성 입력이 UI 에 안 가서 창 모드). 고친 것: 손가락이 빠르게 카드 밖으로 나가면 끌기가 취소되던 문제(실기기에서도 생김), 밀어서 바로 쓰기가 잘못 놓기와 겹쳐 엉뚱하게 쓰이던 문제(밀어서 쓰기 제거).
- **4단계 완료** — 선택 요청: 탁자 모드에서 포켓몬 고르기는 탁자에서 직접(후보 맥동, 고른 것 굵은 틀, 위에 안내 띠·결정), 사이드는 사이드 더미를 눌러 가져오기, 예·아니오·확인 같은 값과 공개 확인은 가운데 대화상자, 카드 고르기는 아래 시트("고를 수 있는 카드만" 유지). 손패 모드는 모두 시트. 테스트: 선택을 **실제 노드(탁자 칸·사이드 카드·시트 버튼·결정)** 를 눌러 처리하며 끝까지 대전.
- **5단계 완료** — 상단 바: ☰ 메뉴(로그 보기·내/상대 트래쉬·항복 2단계 확인), AI 속도 버튼, 자동 진행(켜면 내 차례도 AI 가 둠). AI 연습은 이제 **새 탁자 화면이 기본**(서버 대전은 8단계까지 기존 화면). 게임이 끝나면 턴 종료 자리가 "다시 하기" → 대전 준비로. 테스트: 메뉴·로그·닫기·항복(한 번은 확인만, 두 번째에 항복), 자동 진행만으로 한 판 끝까지, 앱 흐름(대전 준비 → 탁자 → 항복 → 다시 하기 → 대전 준비). 고친 것: 화면 전환 중에 온 "대전 준비로" 신호를 놓치던 문제(매 프레임 확인).
- **6단계 완료** — 연출 큐(`battle/fx.gd`): 드로우(덱 → 손패로 날아감), 카드 사용·특성(가운데 크게 + 설명), 기술(이름 띠 + 공격 포켓몬 돌진), 데미지·회복(숫자 튀어오름 + HP 막대가 그때 줄어듦 + 흔들림·진동), 특수상태(튀어오름), 기절(회색 → 트래쉬로 날아감 + 사이드 띠), 코인(원판 뒤집기 → 앞/뒤 + 이유), 차례 배너, 자리 이동(후퇴·교체 미끄러짐). 속도는 AI 속도를 따름(느리게·보통 1×, 빠르게 2×, 즉시 = 연출 없음), 상대 차례 연출 중 화면을 누르면 건너뛰기, 오프라인 AI 는 연출이 끝날 때까지 기다림. 손패 모드(서버)는 최소 연출(배너·상대 행동 한 줄·진동). 엔진: 기절 사건에 `sid` 추가 (TS·GD 같이, 엔진 비교 일치). 테스트: 2배속 자동 진행으로 끝까지 — 연출이 멈출 때마다 화면 == 상태, HP 지연·기절 칸 남지 않음, 누르기로 건너뛰기. 고친 것: 흔들기·돌진·자리 이동이 겹쳐 칸이 엉뚱한 곳에 멈추던 문제(칸마다 이동 하나만), 칸이 찼는데 빈 칸 틀이 뒤에 남던 문제.
- **7단계 완료** — 준비 단계: 배틀·벤치 포켓몬은 시트 대신 **손패에서 바로 고르기**(기본 포켓몬만 금색 틀, 나머지 흐리게, 배틀 칸·벤치 칸 맥동, 위에 안내 띠·결정). 결과 화면: 마지막 연출이 끝난 뒤 승리/패배/무승부 + 이유(“나/상대” 시점 문구) + 턴·가져간 사이드, 다시 하기(AI 연습)·로그·나가기(서버 대전)·판 보기. 테스트: 준비 단계를 손패 탭으로 처리하며 끝까지 대전, 항복 → 결과 “패배” → 결과 화면의 다시 하기 → 대전 준비. 고친 것: 사이드를 깔기 전에 끝나면 가져간 사이드가 6으로 나오던 문제.
- **8단계 완료** — 서버 대전도 새 화면(손패 모드): 위 상태 줄(덱·사이드·트래쉬, 상대 패·사이드, 재접속 상태, "큰 화면은 게임판에서"), 상대 행동 한 줄 알림, 내 포켓몬 작은 줄(끌어 놓기 대상·기술 말풍선), 큰 손패, 선택은 모두 시트, 결과 화면의 나가기 → 첫 화면. 예전 화면은 `user://ui.json {"classic": true}` 일 때만. 테스트(`node scripts/lan-e2e.ts`, npm test 포함): **실제 서버 + TS AI 상대 + Godot 앱**이 화면 조작만으로 끝까지 대전 → 결과 → 나가기. 고친 것: 서버 메시지의 숫자가 모두 실수로 들어와 "내 차례" 판단이 안 되던 문제(받을 때 정수화), 결과 화면 나가기가 한 화면만 돌아가던 문제(Nav.pop_to_root).
- **9단계 완료** — 스타디움을 가운데 줄에 가로로 눕혀 이름과 함께, 대상 없는 카드(아이템·서포트 등)를 고르면 손패 위에 [사용] 버튼(끌어 올려도 됨), 손패 모드 알림 위치 정리. 화면 크기 테스트: 작은 폰(720×1280)·태블릿(1100×1560)·긴 폰(720×1700)에서 탁자·손패 모드로 실제 게임 — 칸·턴 종료 버튼이 화면 안, 상태와 일치. 전체 `npm test`: 규칙·서버·엔진 비교·앱 화면(헤드리스 + 창 모드 끌어 놓기)·서버 끝-끝.

### 남은 것 (실기기 확인 필요)
- 끌기 손맛, 연출 타이밍(1×·2×), 진동 세기는 실제 폰에서 한 판씩 확인
- 상대 쪽 배치·데미지 숫자 모양은 원작 화면과 대조하지 않음 (스크린샷이 없어서 추정)
- 예전 화면으로 되돌리기: 앱 데이터의 `ui.json` 에 `{"classic": true}`
