# 하스스톤 UI에서 가져올 것 — 두 조사 종합

하스스톤(Blizzard) 대전 화면을 웹으로 조사하고(Claude), 같은 지시를 Fable 헤드리스에 내려 따로 조사한 뒤(원문 `ui-hearthstone-review-fable.md`) 두 결과를 우리 앱의 **지금 구현 상태**와 대조했다. 가져오는 것은 레이아웃·조작·피드백 **패턴**뿐이고, 블리자드 고유 아트·모양(여관 탁자, 마나 수정, 도화선 불꽃, 영웅 대사)은 쓰지 않는다.

조사는 글 자료(위키·공식 포럼·GDC 2015 강연 요약·리뷰)만으로 했고, 실제 게임 화면은 보지 못했다. 대상 지정 화살표, 피해 숫자 색, 상대 카드를 크게 보여주는 위치는 두 조사 모두 본문으로 확인하지 못해 "추정"이다.

## 1. 두 조사가 함께 확인한 하스스톤의 핵심

| 요소 | 동작 | 근거 |
|---|---|---|
| 가능 행동 초록 테두리 | 낼 수 있는 카드, 영웅 능력, 공격 가능한 하수인이 **모두 같은 초록 테두리** | wiki Gameplay (둘 다 확인) |
| 턴 종료 버튼 강조 | 할 수 있는 행동이 없으면 턴 종료 버튼이 초록으로 빛남 | wiki Gameplay (둘 다 확인) |
| 행동 기록 | 왼쪽 세로 타일 7~10개, 내 것 파랑·상대 것 빨강 테두리, 누르면 대상·결과 상세 | wiki History, blizzplanet (Fable 본문 확인, Claude 는 2차 출처) |
| 잘못된 조작 이유 | 마나 부족·준비 안 됨·도발 먼저 등 12가지를 영웅 말풍선으로 | wiki emote (Fable) |
| 덱 장수 | 덱을 가리키면 남은 장수 | wiki Gameplay (둘 다) |
| 턴 시간 | 75초, 마지막 20초에 도화선이 턴 종료 버튼 쪽으로 타들어 감. 직전 턴 무행동이면 다음 턴 약 7초 | wiki Gameplay (둘 다) |
| 선택 창 숨기기 | 발견(3장 중 1장) 선택 중에 **창을 잠깐 숨기고 판을 볼 수 있음** (취소는 불가) | outof.cards Discover (Claude) |
| 재접속 | 60초 안에 복귀, 그동안 게임은 진행. 연출이 25초 넘게 멈추면 자동 재접속 | wiki Gameplay·Reconnection (둘 다) |
| 폰 화면 | 손패는 위 일부만 보이고 탭해야 크게 펼쳐짐. 길게 누르면 상세. "한 번 더 탭"이 느리고 펼치면 판을 가린다는 비판 | trustedreviews, techaeris, toucharcade 요약 |
| 연출 속도 | 속도 조절·건너뛰기 **없음** → 최대 불만("연출이 턴 시간을 먹는다"). 개발자가 발동 연출을 75% 줄였고, 모바일은 뒤처지면 공격 연출을 자동 생략 | 공식 포럼, outof.games, hearthstonetopdecks |
| 물리적 느낌 | 카드를 끌면 기울고, 판을 누르면 먼지가 튐. 이 덕에 터치 이식이 쉬웠음. 7칸 제한은 하수인을 줄여 그리지 않기 위한 UI 결정 | GDC 2015 강연 요약(mmo-champion) |

## 2. 우리 앱과 대조

| 하스스톤 요소 | 우리 앱 지금 | 판정 |
|---|---|---|
| 연출 속도·건너뛰기 | AI 속도 연동 배속(1×/2×/즉시) + 탭해서 건너뛰기 | **이미 더 나음** — 하스스톤 최대 불만을 피함 |
| 턴당 1회 행동 표시 | HUD 칩 "에너지 ✔ 서포트 ○ 후퇴 ○" | 있음 |
| 덱·트래쉬 장수 | 더미 아래 숫자 상시 표시 | 있음 (터치엔 호버가 없어 상시 표시가 맞음) |
| 상대 카드 크게 보여주기 | 연출 큐의 "사용" 큰 카드 | 있음 |
| 가능 행동 표시 | 손패: 못 쓰는 카드를 **어둡게**(쓸 수 있는 카드는 그대로). 포켓몬 칸: 표시 없음 | **부분** |
| 잘못된 조작 이유 | 끌어 놓기를 잘못 놓을 때만 안내 | **부분** |
| 행동 기록 | ☰ 메뉴 → 로그 보기 (화면에 상시 없음) | **부분** |
| 턴 종료 강조 | 없음 | 없음 |
| 선택 창 숨기고 판 보기 | 결과 화면에만 [판 보기] | 없음 |
| 턴 타이머·재접속 | 서버 대전 시간 제한 없음. 재접속은 확인 필요 | 없음/확인 필요 |

## 3. 가져올 후보 (우선순위)

적용 위치: **탁자** = AI 연습 화면, **손패** = 서버 대전 폰, **웹** = 웹 게임판.

| 순위 | 요소 | 우리 방식 | 적용 | 가치 | 난이도 |
|---|---|---|---|---|---|
| 1 | 턴 종료 강조 | 남은 합법 수가 턴 종료(와 후퇴)뿐이면 [턴 종료]가 맥동. 강제는 안 함(정식 룰에선 아끼는 것도 수) | 탁자·손패 | 상 | 하 |
| 2 | 포켓몬 칸 가능 표시 | 기술·특성·후퇴를 쓸 수 있는 내 포켓몬 칸에 손패와 같은 계열의 옅은 테두리. 벤치는 특성이 있을 때만 | 탁자·손패 | 상 | 하 |
| 3 | 못 쓰는 카드 탭 → 이유 한 줄 | 어두운 카드를 탭하면 "이번 턴에 서포트를 이미 썼습니다", "첫 턴에는 진화할 수 없습니다", "에너지를 이미 붙였습니다", "놓을 대상이 없습니다" 등. 이유는 상태(턴 플래그·턴 수·대상 유무)로 추론 | 탁자·손패 | 상 | 중 |
| 4 | 선택 창 잠깐 숨기기 | 선택 창(가운데 창·아래 시트)에 [판 보기] → 창이 접혀 판이 보이고, 아래 띠를 누르면 다시 펼침. 취소는 안 됨 | 탁자·손패 | 상 | 하 |
| 5 | 최근 행동 타일 | 탁자: 왼쪽 가장자리에 최근 5개 작은 카드 타일(내 것/상대 것 색 테두리), 탭하면 그 행동 한 줄과 카드 확대. 손패: 이미 있는 알림 줄을 누르면 최근 기록. 웹: 왼쪽 세로 타일 | 탁자·손패·웹 | 중상 | 중 |
| 6 | 상대 상태 표시 | "상대 생각 중…", 상대 덱 5장 이하면 덱 숫자 경고색 | 웹·손패(탁자는 덱 경고만) | 중 | 하 |
| 7 | 확대 화면 보강 | 특수상태·규칙 용어 풀이, 이번 턴 걸린 효과(도구·스타디움에 의한 데미지·후퇴 변화) 나열 | 전부 | 중 | 중 |
| 8 | 재접속 복귀 | 폰은 화면 꺼짐·앱 전환이 잦으므로 같은 방·같은 자리로 복귀, 상대에겐 "재접속 대기" | 손패·웹 | 상 | 중상 (서버) |
| 9 | 턴 시간 띠 | 방 설정으로 켤 때만. 평소 숨기고 막바지에 턴 종료 버튼 둘레 띠. 웹은 가운데 줄 | 손패·웹 | 하~중 | 중 |
| 10 | 연습 상대 고르기·첫 대전 안내 | AI 덱·난이도 선택, 처음 3판은 다음 행동을 깜빡임으로 안내 | 탁자 | 중 | 상 |

1~4는 서버·엔진 변경 없이 앱 화면만 바꾸면 되고, 이미 있는 합법 수(`legalMoves`)·턴 플래그를 그대로 쓴다. 5는 이미 있는 로그(`BLog`)와 연출 사건을 재사용한다. 8은 서버 작업이라 따로 설계한다.

## 4. 가져오지 않을 것

- **입력을 막는 긴 연출, 기기 성능에 따른 몰래 생략** — 하스스톤의 최대 불만. 우리는 사용자가 고르는 배속·건너뛰기를 유지하고, 건너뛴 내용은 기록에 남긴다.
- **상대의 손패 만지작거림 실시간 공개** — 정보 누출·심리전 도구가 됨. "생각 중" 정도만.
- **탭해야 펼쳐지는 접힌 손패** — "한 번 더 탭"이 느리고 펼치면 판을 가린다는 비판. 우리 부채꼴 손패 유지.
- **피로 피해·손패 10장 초과 파괴·마나 바·하수인 자리 지정** — 포켓몬 정식 룰과 다름(덱이 비면 뽑지 못해 패배, 손패 상한 없음, 에너지는 포켓몬에 붙임).
- **턴 종료 강제 차단** — 튜토리얼에서만. 본 게임에선 아무것도 안 하고 넘기는 것도 정상적인 수.
- **도발형 이모트, 블리자드 고유 모양** — 앱 목적과 맞지 않고, 비주얼은 패턴만.

## 5. 두 조사의 차이

- 둘이 같은 결론: 초록 테두리·턴 종료 강조·기록 타일·재접속이 핵심이고, 연출 속도 조절이 없는 것이 최대 약점.
- Fable 만 확인: 기록 타일 색 규칙, 잘못된 조작 12가지 말풍선, 튜토리얼 구성(빨간 화살표·턴 종료 차단·질 수 없는 대전), 관전 모드 세부.
- Claude 만 확인: 선택 창(발견)을 숨기고 판을 보는 기능, 모바일 공격 연출 자동 생략(개발자 발언), 발동 연출 75% 단축, GDC 강연의 "7칸 제한은 UI 결정"·"물리적 느낌".
- Fable 이 1순위로 꼽은 "연출이 입력을 막지 않게"는 우리 앱에 배속·건너뛰기가 이미 있어 순위를 내렸다.

## 부록: Fable 에 준 지시 (요약)

우리 프로젝트(정식 룰, 탁자/손패 두 모드, 이미 구현된 것 목록)를 설명하고, 하스스톤의 배치·조작·피드백·정보 표시·편의·비판받은 점을 출처 URL 로 확인해 "가져올 후보 표(적용 위치·가치·난이도·정식 룰 충돌)", "가져오면 안 되는 것", "우선순위와 단계"를 한국어 보고서로 내라고 지시. 블리자드 고유 비주얼은 제외, 확인 못 한 것은 "추정"으로 표시.

## 진행 기록

- **1~4번 적용** (`godot/scripts/battle/hints.gd` BHint + 대전 화면)
  - 턴 종료 강조: 남은 수가 턴 종료(·후퇴)뿐이면 [턴 종료]가 천천히 맥동하고, 이때는 "한 번 더 누르기" 확인 없이 바로 끝남.
  - 준비된 포켓몬: 기술·후퇴(배틀 포켓몬)나 특성(그 칸)을 지금 쓸 수 있으면 가는 초록 틀. 카드를 고르거나 선택 중일 때는 숨김.
  - 못 쓰는 이유: 어두운 손패를 탭하거나 잘못 끌어 놓으면 이유 한 줄 (에너지·서포트·스타디움 1회, 선공 첫 턴 서포트, 진화 전 포켓몬 없음·첫 턴·이번 턴에 나옴, 벤치 가득, 도구 자리 없음, 아이템 잠금, 이상한사탕 조건). 카드별 특수 조건은 일반 문구.
  - 판 보기: 아래 시트·가운데 창 선택 중 오른쪽 위 [판 보기] → 창이 접히고 판·손패가 보임(포켓몬 탭 = 크게 보기), 가운데 [▲ 선택으로 돌아가기] 또는 뒤로 가기로 복귀. 선택은 그대로.
  - 테스트 `hints`: 판정 단위 검사 + 탁자·손패 모드 실제 게임에서 멈출 때마다 화면 표시 == 판정, 못 쓰는 카드 탭 → 이유(선택 안 됨), 선택 창마다 판 보기 왕복.
- **6번 적용** (상대 상태)
  - 상대 차례에 연출이 끝났고 내가 고를 것도 없으면 아래 칩 자리에 "AI 생각 중…"(연습) / "상대 생각 중…"(서버 대전). 상대 손패를 만지는 모습은 보여 주지 않음.
  - 덱 5장 이하(덱이 비면 뽑지 못해 패배): 탁자 모드 덱 숫자가 주황 경고색, 손패 모드 상태 줄에 "⚠"(상대 덱은 5장 이하일 때만 표시).
  - 테스트 `fx`: 연출이 끝날 때마다 "생각 중" 표시 == 상태, 덱 경고 == 장수.
